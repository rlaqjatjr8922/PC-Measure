캡처 이미지 전달 변경 (2026-10-04)

대상: screen_capture, screen_capture_monitor, screen_screenshot(mode=capture/read)의 이미지 응답.
흐름: 손님 PC에서 이미지 바이트 수신 → 제어 PC 임시 파일 저장 → 저장한 파일 읽기 → MCP 이미지 블록 또는 HTTP 이미지 전송.
이 전달 과정은 손님 PC의 파일 저장 기능을 호출하지 않습니다.

위치: 제어 서버를 실행하는 PC의 %TEMP%\pc-control-captures-* 폴더.
원본은 PNG/JPEG 등 수신 형식으로 보관합니다. MCP 미리보기는 기존처럼 최대 1920픽셀 JPEG입니다.
응답 메타데이터의 local_path에서 원본 임시 파일 위치를 확인할 수 있습니다.
서버 정상 종료 시 임시 폴더를 제거합니다. 새 이미지 저장 시 1시간이 지난 파일을 정리하며 최대 100개/256MB로 제한합니다.
이미지 한 장의 제한은 32MB입니다. 강제 종료 시 운영체제 임시 폴더에 잔여 파일이 남을 수 있습니다.

명시적으로 실행하는 screenshot의 save 모드, 검증용 저장 이미지, 별도로 켠 조작 기록의 스크린샷 저장은 기존 기능입니다. 이번 변경은 이미지 응답 전송 경로에 적용됩니다.

반영: 제오용/PC-Control-Server의 제어 서버를 재시작합니다. 이 변경에는 손님용 EXE 재설치가 필요하지 않습니다.
검증: 제어 서버 검사 22개 통과. 원격 캡처 요청이 한 번만 발생하는지, 로컬 원본과 HTTP 응답의 바이트 일치, MCP 이미지 생성, 실제 로컬 파일 읽기, 경로 제한, 임시 파일 개수 제한을 검사했습니다.
